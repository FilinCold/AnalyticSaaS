# MVP_SCOPE — окончательный scope MVP

## One Job MVP

Пользователь создаёт **исследование (Research)** по нише → система собирает/принимает сигналы → строит **кандидатов идей** → считает скоры → показывает **основной список** (только прошедшие пороги) и карточку идеи с build- и sales-блоками.

## Входит в MVP

1. **Аккаунт:** регистрация/вход (email+password или magic link — по решению стека).
2. **Research:** создать исследование (тема/ниша + опциональные ключевые слова).
3. **Сигналы (минимально):**
   - ручной ввод/вставка текста сигнала;
   - **три** автоматических адаптера: **Hacker News**, **Product Hunt**, **Reddit** (`DECISIONS.md` § «Стек MVP»); manual paste остаётся;
   - хранение сырого текста + метаданных источника.
4. **Pipeline (фон):** normalize → extract pain → cluster → generate idea draft → score → filter → persist.
5. **Триггеры обновления идей** (сбор сигналов + pipeline для Research):
   - **Первый запуск** — автоматически после создания Research при **≥1** сигнале (manual и/или ingest адаптера); для демо/E2E рекомендуется ≥3;
   - **Вручную** — кнопка «Обновить идеи» / «Запустить анализ» в UI Research;
   - **По расписанию** — автоматически **раз в 3 календарных дня** для каждого активного Research (re-ingest адаптера при наличии + полный pipeline).
6. **Основной список идей:** только идеи, прошедшие все 4 порога; сортировка по Opportunity Score.
7. **Карточка идеи:** шаблон one-job; атрибуты; скоры; обязательные build-поля (Часть 4); обязательные sales-поля (Часть 5); `fourteenDayBuildPlan`; go/kill (`continue_criteria` / `stop_criteria`).
8. **Статусы идеи:** `candidate` | `recommended` | `narrowed` | `excluded` (+ причина исключения).
9. **Повторный прогон** скоринга после ручного сужения полей (без полного re-ingest).

## Ручной happy path (E2E / Definition of Done для F8-01)

Пользователь за один проход (без проверки cron):

1. регистрируется;
2. создаёт Research «возвраты в e-commerce» (или аналог);
3. добавляет ≥3 сигнала (вручную и/или через адаптеры) **или** pipeline стартует автоматически после первых сигналов;
4. видит автозапуск pipeline (первый раз) **или** нажимает «Обновить идеи»;
5. ждёт статус job (queued → running → succeeded / failed);
6. видит ≥1 идею в основном списке **или** явный список excluded с причинами;
7. открывает карточку recommended-идеи со всеми обязательными полями и скорами;
8. понимает, что делать дальше по `fourteenDayBuildPlan` и sales-блоку.

_(Плановое обновление раз в 3 дня проверяется отдельно — cron/job, не в ручном vertical slice.)_

## Не входит в MVP

См. `NON_GOALS.md`. Кратко: биллинг AnalyticSaaS, мультитенант-орги, много источников, кодоген micro-SaaS, лендинг-билдер, авто-outreach, маркетплейс идей, мобильное приложение.

## Контроль ширины scope платформы

AnalyticSaaS **сама** подчиняется one-job: не превращаться в «AI-платформу для предпринимателей». Любая фича вне vertical slice — post-MVP.
