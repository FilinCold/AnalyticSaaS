# PRODUCT_PRINCIPLES — ключевые продуктовые ограничения

> SSOT продуктовых ограничений. Формулы скоринга — в `AI_PIPELINE.md`. Scope — в `MVP_SCOPE.md` / `NON_GOALS.md`.

## Назначение

AI-система поиска коммерчески проверяемых идей для micro-SaaS (см. `VISION.md`).

## Антипозиционирование

- не Google Analytics / Amplitude / product analytics;
- не кодогенератор найденного продукта;
- не универсальная бизнес-платформа.

## Принципы отбора идей (найденный micro-SaaS)

1. **One job:** один пользователь → одна проблема → одно основное действие → один результат.
2. «Одна функция» = одна законченная работа, не одна кнопка; шаги основного flow допустимы.
3. Обязательный шаблон:  
   `[пользователь] передаёт [данные] и получает [результат], который сейчас получает медленным/дорогим/неудобным способом.`
4. Исключать: платформы, CRM, ERP, экосистемы, «для всего бизнеса», несколько несвязанных аудиторий, многомодульность, длинный список фич.
5. Создатель идеи: соло + AI agent; без требования команды/DevOps/дизайнера/продаж как условия сборки.
6. Полный цикл до старта привлечения ≤ **14 календарных дней**; оценка не «как у senior» без поправки + резерв на AI/интеграции/деплой.
7. Scope идеи: 1 функция, 1 flow, ≤3 вспомогательных возможности, минимальный UI/данные/интеграции, managed-сервисы.
8. Если не влезает в 14 дней: сузить → убрать secondary → manual fallback → переоценка → исключить.
9. Быстрая проверка продаж обязательна; достаточный спрос ≠ лайки/комменты/интерес без действия.

## Пороги основного списка

| Метрика | Порог |
|---|---|
| One Job Score | ≥ 80 |
| AI Buildability Score | ≥ 75 |
| estimatedBuildDays | ≤ 14 |
| First Sale Potential | ≥ 70 |

Ранжирование внутри списка — `Opportunity Score` (см. `AI_PIPELINE.md`).

## Принципы самой платформы AnalyticSaaS

1. One job платформы — см. `VISION.md`.
2. Не расширять продукт самостоятельно; не добавлять «на будущее».
3. MVP = минимальный vertical slice (`MVP_SCOPE.md`).
4. Код — только после согласования плана владельцем.

## Процесс работы над ТЗ

Части требований = единое ТЗ; новое > старое; неясности → `OPEN_QUESTIONS.md`.
