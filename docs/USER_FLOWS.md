# USER_FLOWS — пользовательские сценарии MVP

## Актор

Соло-создатель (профиль Части 3).

## Flow A — Happy path (vertical slice)

1. Регистрация / вход.
2. Попадает на **ленту идей** (+ сводная статистика / дата обновления).  
   _(Создание Research пользователем — не шаг flow.)_
3. Система уже собрала или собирает сигналы через адаптеры (HN / PH / Reddit) в system feed; при необходимости E2E — seed/manual signals.
4. **Первый раз:** pipeline стартует **автоматически** (если есть сигналы) — пользователь видит статус без обязательного клика.
5. Ждёт статус job (queued → running → **succeeded** / failed). UX: «Готово» / «Ошибка».
6. В ленте видит **Рекомендованные** по Opportunity Score.  
   _(Вкладки «Суженные» / «Исключённые» — Flow B/C.)_
7. Открывает карточку: one-job, скоры, build, sales, go/kill.
8. (Опционально) правит поля сужения → «Пересчитать скоры».
9. (Опционально) «Обновить ленту» для повторного сбора вне расписания.

## Flow A2 — Плановое обновление (раз в 3 дня)

1. Cron находит system feed с `last_pipeline_finished_at` > 3 календарных дней назад.
2. Автоматически: re-ingest адаптеров → `pipeline.run` (`trigger=scheduled`).
3. Пользователь при входе видит обновлённую ленту и метку «Обновлено …» / статус последнего run.  
   _(UX-копия: актуальность окна 3–5 дней.)_

## Flow B — Нет идей в основном списке

1–5 как в Flow A (шаг 4 — авто или manual).  
6. Лента recommended пуста; видит stats + «Исключённые» с причинами (порог / не one-job / days / sales).  
7. Ждёт следующего scheduled refresh или жмёт «Обновить ленту».

## Flow C — Идея сужена системой

1. Во вкладке **«Суженные»** или в карточке статус `narrowed`: показаны `featuresExcludedToFitDeadline` и пересчитанные скоры.  
2. Пользователь принимает narrowed-версию (→ rescore может перевести в `recommended`) или исключает.

## Flow D — Pipeline завершился с ошибкой

1. Статус run = `failed`; пользователь видит краткое сообщение (без секретов/стека).  
2. Кнопка «Повторить» / «Обновить ленту» → новый `pipeline.run` с `trigger=manual`.  

## Flow E — (вторичный) Admin / E2E signals

1. Dev/E2E добавляет manual signals в system feed **или** дергает ingest адаптера.  
2. Далее как Flow A с шага 4.  
   _(Не основной пользовательский сценарий.)_
