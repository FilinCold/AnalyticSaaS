# PROBLEM — какую боль решаем

## Боль

Соло-создатели тратят время на идеи, которые:

- слишком широкие (платформы, CRM, «для всего бизнеса»);
- технически неподъёмны без команды / сильного fullstack;
- нельзя собрать и вывести на проверку продаж за разумный срок;
- нельзя быстро проверить готовность платить (интерес ≠ оплата).

Существующие инструменты (тренды, форумы, аналитика продуктов) **не** дают одновременно:

1. узкий one-job micro-SaaS;
2. пригодность для сборки соло + AI-агентом;
3. укладку в ≤14 календарных дней (включая деплой, лендинг, оплату, старт привлечения);
4. план быстрой проверки первой продажи с жёсткими критериями спроса.

## Для кого

**Пользователь AnalyticSaaS** = профиль создателя из ТЗ (Часть 3): один человек без команды, без уверенного fullstack; основной код будущего micro-SaaS пишет AI coding agent.

## Цена бездействия

Месяцы на «интересную» идею → провал на сборке или на продаже → нет сигнала go/kill.

## Как AnalyticSaaS закрывает боль

Сигналы → структурированные идеи → скоринг → фильтр → карточка с build-планом и sales-планом → пользователь выбирает и проверяет продажами (вне платформы или с минимальной поддержкой в MVP).
